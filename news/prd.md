# 뉴스 브리핑 기능 PRD

> 기반 문서: `최근뉴스_기술명세서.md`
> 본 PRD에서는 뉴스 검색 API를 명세서 원안(Claude API `web_search`)이 아닌 **네이버 뉴스 검색 API(Client ID/Secret 인증 방식)** 로 교체하여 작성한다.

---

## 1. 배경 및 목표

### 배경
알람 웹앱 사용자는 아침에 알람이 울린 뒤 자연스럽게 그날의 주요 뉴스를 접하고 싶어 한다. 현재 앱은 알람과 실시간 날씨 표시 기능만 제공하며, 뉴스 소비를 위해서는 별도 앱/브라우저로 이동해야 하는 불편이 있다.

### 목표
- 알람 웹앱 내에서 최신 뉴스 5개를 검색하여 카드 형태로 보여준다.
- 사용자가 화면을 보지 않아도 될 수 있도록, 브라우저 TTS(Web Speech API)로 뉴스를 읽어준다.
- 뉴스 검색에 사용되는 네이버 API 인증 정보(Client ID/Secret)가 클라이언트에 노출되지 않도록 서버(Supabase Edge Function) 경유 구조를 갖춘다.
- 뉴스 브리핑 기능의 장애가 알람의 본질적 기능(정해진 시각에 소리로 사용자를 깨우는 것)을 절대 방해하지 않도록 한다.

---

## 2. 사용자 스토리

1. **알람 사용자로서**, 알람이 울렸을 때(또는 별도 버튼 클릭 시) 오늘의 주요 뉴스 5개를 화면에서 바로 확인하고 싶다.
2. **바쁜 아침 시간의 사용자로서**, 화면을 직접 보지 않고도 뉴스 제목과 요약을 음성으로 듣고 싶다.
3. **사용자로서**, 개별 뉴스 카드마다 "읽어주기" 버튼을 눌러 원하는 뉴스만 골라 들을 수 있기를 원한다.
4. **사용자로서**, "전체 재생" 버튼 하나로 5개 뉴스를 순서대로 이어서 들을 수 있기를 원한다.
5. **사용자로서**, 뉴스 브리핑 기능에 오류가 발생하더라도 알람 소리는 반드시 정상적으로 울리기를 기대한다(뉴스 기능이 알람의 신뢰성을 해치지 않아야 함).
6. **사용자로서**, 이전에 검색된 뉴스가 아니라 항상 그 시점 기준 최신 뉴스를 보고 싶다.

---

## 3. 기능 요구사항

### 3-1. 뉴스 검색
- FR-1: 사용자가 "뉴스 브리핑" 버튼을 클릭하면 최신 뉴스 5개를 검색하여 표시한다.
- FR-2: 뉴스 검색은 React 클라이언트가 Supabase Edge Function을 호출하고, Edge Function이 내부에서 네이버 뉴스 검색 API를 호출하여 결과를 받아오는 프록시 구조로 동작한다.
- FR-3: 네이버 뉴스 검색 API 응답(제목, 요약/설명, 언론사, 링크, 발행일 등)을 정제하여 `{ title, summary, source, url, pubDate }[]` 형태로 클라이언트에 반환한다.
  - 네이버 API 응답에는 HTML 태그(`<b>` 등)와 HTML 엔티티가 포함될 수 있으므로 Edge Function 단에서 이를 제거/정제한다.
- FR-4: 검색 결과가 5건 미만이거나 0건인 경우, 사용자에게 "표시할 뉴스가 없습니다" 등 안내 메시지를 보여준다.

### 3-2. 뉴스 표시(프론트엔드)
- FR-5: 뉴스 카드 리스트 컴포넌트로 제목/요약/출처를 표시한다.
- FR-6: 카드별로 "읽어주기" 버튼과 재생/정지 상태를 표시한다.
- FR-7: "전체 재생" 컨트롤을 제공하여 5개 뉴스를 순서대로 낭독한다. 전체 재생 중에는 정지 버튼을 노출한다.
- FR-8: 기존 알람 UI와 통일된 다크 테마 스타일을 적용한다.

### 3-3. 뉴스 읽어주기(TTS)
- FR-9: 브라우저 내장 Web Speech API(SpeechSynthesis)를 사용하여 별도 서버/API 없이 한국어(`ko-KR`) 음성으로 낭독한다.
- FR-10: 개별 카드의 "읽어주기" 클릭 시 해당 뉴스의 제목+요약을 낭독한다.
- FR-11: 재생 중 다른 카드의 "읽어주기"를 클릭하거나 정지를 누르면 현재 재생 중인 음성을 즉시 중단하고 새 음성으로 전환(또는 정지)한다.
- FR-12: TTS 지원 여부(`window.speechSynthesis` 존재 여부)를 확인하여, 미지원 브라우저에서는 "읽어주기" 기능을 비활성화하고 안내 문구를 표시한다.

### 3-4. 에러 처리
- FR-13: 뉴스 검색(네이버 API 호출, Edge Function 호출) 실패 시 뉴스 영역에만 에러 메시지를 표시하고, 알람의 다른 기능(알람 설정/소리 재생 등)에는 영향을 주지 않는다.

---

## 4. 비기능 요구사항 (보안 최우선)

### 4-1. 보안
- **NFR-1 (필수)**: 네이버 API 키(Client ID/Secret)는 프론트엔드(React 번들, 브라우저 네트워크 탭, 클라이언트 소스 등) 어디에도 노출되지 않는다. 반드시 Supabase Edge Function 등 서버 사이드 환경 변수/Secret으로만 보관하고 사용한다.
- **NFR-2**: Edge Function은 CORS 및 허용 Origin을 제한하여, 인가되지 않은 외부 클라이언트가 프록시를 통해 네이버 API를 무단 호출하지 못하도록 한다.
- **NFR-3**: 클라이언트에서 Edge Function으로의 요청/응답 로그에 API 키, 인증 토큰 등 민감 정보가 남지 않도록 한다.
- **NFR-4**: Supabase 프로젝트의 Edge Function 환경 변수는 저장소(git)에 커밋되지 않으며, `.env`/예시 파일에는 실제 값 대신 placeholder만 사용한다.

### 4-2. 데이터 처리
- **NFR-5 (필수)**: 뉴스 데이터는 DB에 저장하지 않고, 매 요청마다 네이버 API를 실시간 호출하여 조회한다. (명세서 3-2의 `news_cache`, `user_news_status` 등 캐싱/DB 저장 방안은 본 PRD 범위에서 채택하지 않는다.)

### 4-3. 가용성/안정성
- **NFR-6 (필수)**: 뉴스 브리핑 기능(검색 실패, Edge Function 오류, TTS 오류 등 어떤 장애가 발생하더라도) 알람의 핵심 기능인 "정해진 시각에 알람 소리를 재생하는 것"은 반드시 정상 동작해야 한다. 뉴스 관련 코드는 알람 재생 로직과 예외 처리 상에서 분리되어, 뉴스 기능의 예외가 알람 재생을 막거나 지연시키지 않아야 한다.
- **NFR-7**: 네이버 API 응답 지연/타임아웃 시 일정 시간(예: 수 초) 내에 타임아웃 처리하여 UI가 무한 로딩 상태에 빠지지 않도록 한다.

### 4-4. 성능
- **NFR-8**: TTS 부담을 줄이기 위해 뉴스 요약은 짧게(예: 명세서 기준 3문장 또는 그에 준하는 길이) 제한한다.

---

## 5. 범위 제외 (Out of Scope)

- 카테고리 필터(정치/경제/IT 등) 기능 — 추후 확장 항목으로 별도 논의
- 사용자별 "읽음 처리", "즐겨찾기" 등 개인화 기능 (명세서 3-2의 `user_news_status` 관련 기능)
- 뉴스 검색 결과의 DB 캐싱/이력 저장 (`news_cache` 테이블) — 본 기능은 항상 실시간 조회만 수행하므로 범위 제외
- 다국어(한국어 외) 뉴스 검색 및 TTS 지원
- 뉴스 요약의 자체 재가공(문장 재작성, 요약 품질 개선을 위한 별도 AI 처리) — 네이버 API가 제공하는 description을 그대로 정제하여 사용
- 뉴스 콘텐츠에 대한 사용자 댓글/공유 등 소셜 기능

## 6. Open Questions

명세서 6번("향후 논의 필요 항목")에 근거하여, 아직 확정되지 않은 항목을 아래와 같이 분리한다. 이 항목들은 확정된 사양이 아니며, 추가 논의 후 결정되어야 한다.

### 6-1. 재생 타이밍 미확정
- 알람이 울릴 때 뉴스 브리핑을 **자동으로 트리거**할지, 아니면 사용자가 별도 버튼을 눌러야만 실행되는 **수동 트리거** 방식으로 할지 미확정.
- 자동 트리거를 채택할 경우, 알람 소리와 뉴스 음성 낭독이 겹치지 않도록 어떤 순서/딜레이로 재생할지(예: 알람 소리 종료 후 N초 뒤 뉴스 낭독 시작 등) 미확정.
- 전체 자동 재생(5개 순차 낭독) 중 사용자가 알람을 끄거나 앱을 벗어나는 경우의 재생 중단/유지 정책 미확정.

### 6-2. 검색 키워드 미확정
- 네이버 뉴스 검색 API 호출 시 사용할 **검색어/쿼리**가 미확정 (예: 고정 키워드 "오늘의 뉴스"류를 사용할지, 네이버 뉴스 API의 인기/헤드라인성 결과를 가져오는 별도 파라미터를 사용할지, 사용자가 키워드를 직접 입력하게 할지 등).
- 카테고리(정치/경제/IT 등) 필터를 1차 버전에 포함할지 여부 및, 포함한다면 어떤 카테고리 값을 네이버 API 파라미터로 매핑할지 미확정.
- "최신"의 기준(정렬 방식: 네이버 API의 `sort=date` 등 최신순 vs 정확도순)이 미확정.

### 6-3. 기타 (명세서 6번 원문 기반)
- UI 디자인: 화면당 표시 개수(5개 고정 여부), 카드 스타일, 다크 테마 세부 적용 방식 미확정.
- 캐싱/갱신 정책: 본 PRD는 "매 요청 실시간 조회"를 원칙(NFR-5)으로 하지만, 동일 세션 내 반복 클릭 시 재요청을 허용할지, 최소 재요청 간격을 둘지는 미확정.

## 7. 성공 기준

- SC-1: 사용자가 "뉴스 브리핑" 버튼을 클릭하면 3초 이내(네트워크 정상 시) 뉴스 5개 카드가 표시된다.
- SC-2: 브라우저 네트워크 탭, 프론트엔드 소스 코드, 번들 결과물 어디에서도 네이버 API Client ID/Secret이 발견되지 않는다.
- SC-3: 뉴스 검색/Edge Function/TTS 중 어느 하나가 강제로 실패하는 상황을 재현했을 때, 알람 소리는 영향 없이 정상적으로 울린다.
- SC-4: 동일한 뉴스 요청을 반복 호출했을 때 DB가 아닌 네이버 API로부터 매번 새로 데이터를 받아오는 것이 네트워크 로그로 확인된다(캐시/DB 저장소를 거치지 않음).
- SC-5: "읽어주기" 및 "전체 재생" 클릭 시 한국어 음성으로 정상 낭독되며, 재생 중 다른 카드 클릭/정지 클릭 시 이전 음성이 즉시 중단된다.
- SC-6: TTS 미지원 브라우저에서 앱이 에러 없이 동작하고, 적절한 안내 문구가 표시된다.
